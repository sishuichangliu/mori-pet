## M1.1 修复记录

1. **抖动** —— 去掉 `morichan` 自带物理（physics3 引用了不存在的 `PARAM_ANGLE_X`），改用 `morichan.pet.model3.json`（无 Physics 段），日志确认 `physics=false`；两帧像素差仅 0.34/255
2. **参数不生效** —— 参数注入点从 `internalModel.update` 移到 `motionManager.update` 之后（否则被每帧重置）
3. **无法点击/拖动** —— 三处叠加原因：
   - 窗口 `focusable:false` → Windows 不派发鼠标事件，改 `true`
   - 依赖 `forwarded mousemove` 切换穿透，按下瞬间常处于穿透态 → 改为主进程**轮询光标**决定
   - alpha 掩码格子太粗（64×87、阈值 24）导致细发丝处判为空 → 提到 96×130、阈值 8、3×3 膨胀；最终简化为**按窗口矩形接管**
4. 吸附阈值 64px → 10px

## M1.2 修复记录（眨眼）

**现象**：她反复在"白眼"和"正常眼"之间闪，像抽搐。

**原因**：`model3.json` 的 `Groups.EyeBlink` 只有一个 id `ParamEyeA`，SDK 自带的眨眼驱动在这个单参数模型上把值来回写（0↔1），而 `ParamEyeA` 的语义是「**眼睛形态切换**」：0 = 正常，1 = 白眼/闭眼 —— 于是变成了高频切换。

**处理**：

1. 把 `morichan.pet.model3.json` 里的 `Groups.EyeBlink.Ids` 清空 → 停用 SDK 自动眨眼
2. 自己实现眨眼（在 `applyParams` 里）：
   - 每 **2.5~6 秒**随机一次
   - 一次眨眼 **260ms**：90ms 闭上 → 70ms 保持 → 100ms 睁开
   - 平时 `ParamEyeA` 强制为 0

**实测**：16 秒内 3 次眨眼，间隔 4.3~5.8 秒，`blink start` / `blink end` 成对出现，抖动消失。

### 顺带测到的参数取值范围（重要）

| 参数 | min | max | 默认 | 说明 |
|---|---|---|---|---|
| `ParamEyeA` | 0 | 1 | 0 | 0 正常 / 1 白眼（闭眼） |
| `ParamMouthA` | 0 | 1 | 0 | 嘴形 |
| `ParamTail` | -1 | 1 | 0 | 尾巴（负数另一侧） |

| `ParamTear` | 0 | 1 | 0 | 眼泪 |

## M1.3 修复记录（眨眼 + 参数体系纠正）

**重大纠正**：morichan 不是"只有 8 个参数"，而是 **47 个**（39 个标准 `PARAM_*` + 8 个自定义 `Param*`）。
之前的扫描区分大小写、只搜了 `Param`，把大写标准参数全漏了。

**眨眼**（本次核心修复）

- 错误做法：把 `Groups.EyeBlink` 绑到 `ParamEyeA` → 那是"眼睛形态"开关（0 正常 / 1 白眼），SDK 每帧来回写就成了高频白眼切换

## M1.4 修复记录（视线跟随方向）

**现象**：她会跟着动，但看的不是指针方向。

**两个原因**

1. **只收到窗口内的鼠标事件** —— 原来靠渲染进程的 `mousemove`，受限窗口范围；光标在桌面其它位置时基本没映射
   → 改为主进程每 60ms 轮询全局光标，`webContents.send('cursor', …)` 推给渲染进程
2. **方向符号** —— 最终以肉眼实测为准（我的瞳孔质心测量不可靠，Q 版头一转整个脸的像素重心就漂移）
   → `xSign = 1`、`ySign = 1`，集中放在 `src/app.js` 顶部的 `LOOK` 常量里；托盘另有「视线左右/上下反向」开关可现场翻转

**幅度**：`ANGLE_X` ±28°、`ANGLE_Y` ±22°、`EYE_BALL` ±1.0、`BODY_ANGLE_X` ±7°

**量化验证**（瞳孔质心，越小越靠左）

## 开关她（M1.5）

三种方式，任选：

| 方式 | 操作 |
|---|---|
| **桌面快捷方式** | 双击「**morichan 开关**」→ 显示 / 隐藏（图标是 Electron 的） |
| **全局热键** | `Ctrl + Alt + M` |
| **托盘菜单** | 右键粉色圆点 → 显示 / 隐藏 / 退出 |

实现原理：

- 主进程用 `requestSingleInstanceLock()` 保证只有一个实例
- **再次启动程序时不会开第二个进程**，而是给已运行实例发 `second-instance` 事件 → 切换显示/隐藏
- 因此桌面快捷方式本质就是"再启动一次"：没运行就启动，运行中就当开关
- 隐藏 ≠ 退出：进程还在，显存/CPU 还是占着一点；要彻底关掉用托盘「退出」

实测日志：

```
[toggle] second instance -> toggle
[toggle] hidden
[toggle] second instance -> toggle
[toggle] shown
```

## 互动反应（M1.7）

点击按**区域**区分，拖拽按**速度**区分：

| 触发 | 判定 | 反应 |
|---|---|---|
| 摸头 | 点击上半部（y < 42%） | 竖耳朵 + 头顶星星环亮起（ParamStar + ParamFoxear） |
| 戳身体 | 点击中段 | 耳朵耷拉（ParamFoxear 负向，1.8s 恢复） |
| 拽尾巴 | 点右侧（x > 66%，y 42%~92%） | 尾巴高频甩动（ParamTail 17Hz × 1.4s） |
| 甩飞 | 拖拽速度 > 1100 px/s 且位移 > 80 | 播 dizzy 动作 4.6 秒：星星环全开 + 举手 + 脸红 + 闭眼 |

实现要点：

- zoneAt(x, y) 按模型包围盒比例分区
- 
eact(kind) 统一入口，带交互计时（同时清空眼泪）

## M1.8 修复：动作放完后卡姿势

**现象**：甩飞眩晕结束后，她的手一直举着、脸红不褪、表情僵着。

**原因**：dizzy.motion3.json 会驱动一堆我们平时**不接管**的参数：

PARAM_CHEEK、PARAM_BROW_*、PARAM_EYE_FORM、PARAM_MOUTH_FORM、PARAM_BASE_* 等。

**处理**：加 RESET_PARAMS 表（31 个参数 + 各自默认值），在 
c.dizzy 归零时调用

esetPose() 一次性复位。日志确认 pose reset，6 秒后截图已恢复正常站姿。

## M2.5 修复：生气表情不消失

**现象**：右键播「生气」后，她一直保持白眼+撇嘴的生气脸。

1. **动作是循环的** —— 所有 `.motion3.json` 的 `Meta.Loop` 都是 `true`，
   动作播完后仍在继续写参数，`resetPose()` 复位完又被覆盖回去
2. **复位表漏了两个自定义参数** —— `anger_hold` 会驱动 `ParamEyeA`（`1` = 白眼）
   和 `ParamMouthA`（嘴型），而我的 `RESET_PARAMS` 只列了标准 `PARAM_*`，这两条不在表里

**处理**

- 34 个动作文件统一改 `"Loop": false`
- `resetPose()` 里先 `stopAllMotions()` 再复位（双保险）
- `RESET_PARAMS` 补上 `ParamEyeA` / `ParamMouthA` / `ParamTail` / `ParamTear` /
  `ParamStar` / `ParamStartRuning` / `ParamFoxearL` / `ParamFoxearR`

**验证**：播 `anger_hold` → 2.86s 后 `pose reset` → 截图已恢复正常眼型与微笑。

## M2.6：眩晕去掉举手

**需求**：播放「眩晕」时不举手，其他效果（星环、眼泪、脸红、闭眼）保留。

**走过的弯路**：先把 `dizzy.motion3.json` 里的 `PARAM_ARM_*` / `PARAM_HAND_*` 曲线删掉，
结果动作**整个失效**——因为 `Meta.CurveCount` 写的是 36，实际只剩 30 条，
解析器按 Meta 计数分配，数量对不上就直接不播了。（已从 `.bak` 恢复）

**最终做法**：不改动作文件，改代码。

```js
const PIN_ARMS = ['PARAM_ARM_L_01','PARAM_ARM_L_02','PARAM_ARM_R_01','PARAM_ARM_R_02',
                  'PARAM_HAND_L','PARAM_HAND_R','PARAM_LEG_L','PARAM_LEG_R'];
// rc.dizzy > 0 期间，每帧把这些参数钉回 0
```

原理：`applyParams` 在 `motionManager.update` **之后**执行，
所以我们的写入优先级高于动作 —— 动作写它的，我们覆盖回来。

验证：眩晕中截图 —— 星环在头顶转、脸红、闭眼、**双手自然垂下**。

## M2.9：摇晃眩晕

**需求**：鼠标快速晃动她时触发眩晕，持续时长 = 晃动时长，无冷却。

**实现链路**

1. 主进程 `dragTimer`（16ms）每 4 拍算一次实时速度：
   `speed = 光标位移 / 时间`，通过 IPC `drag-shake` 推给渲染进程
2. 渲染进程：`speed > 1200 px/s` 时进入眩晕 —— 播放 `dizzy` 动作（第 1 次触发时），
   并把 `rc.dizzy` 刷到 0.5s 续命；同时累计 `shakeMs`
3. 松手时按累计时长结算：`rc.dizzy = clamp(shakeMs/1000, 0.8, 4.6)`

**效果**：晃动越久，晕得越久。期间手臂由 `PIN_ARMS` 钉住（不举手），
星星环/眼泪/脸红/闭眼全部来自 `dizzy` 动作本身。

## M2.10：修复「按住拖动时她一直变大」

**现象**：按住她拖动，模型持续变大；松手后才缩回去。

**根因**

透明无边框窗口在 `--disable-gpu` 下，拖动时渲染进程上报的视口尺寸会漂移
（实测 `innerWidth/innerHeight` 从 383×522 一路涨到 416×559）。

原代码的 `resize` 处理里会调用 `fit()`：

```js
const s = app.screen.height / model.height;   // 高度变大 → s 变大
```

于是每次拖动事件都把她按"更大的高度"重新缩放一次 → **看起来一直在变大**，松手后视口恢复才缩回去。

**修复（三处）**

1. **缩放只算一次** —— `baseScale` 首次计算后固定，之后任何 resize 都不重算
2. **画布固定 380×520** —— `#stage` 与 `canvas` 用固定 px，不再 100% 拉伸；并移除 `resize` 监听
3. **坐标换算** —— 命中判定改用 `app.view.getBoundingClientRect()` 把客户端坐标映射到画布坐标，
   保证改尺寸后点击分区（头/身/尾）依旧准确

**验证**

| | 模型像素高度 | 画面高度 |
|---|---|---|
拖动前 | 628 px | 653 |
拖动中 | **626 px** | 710 |

模型像素尺寸基本不变（628 → 626），不再随拖动放大。

命中分区回归测试（坐标换算后）：

```
[pet] tap zone = head at 184 100
[pet] tap zone = body at 192 322
[pet] tap zone = tail at 328 338
```

### 实现方式（关键：不是简单缩放模型）

如果只放大 `model.scale`，她会**顶出画布、被裁掉头**。所以做的是**窗口 + 画布一起长高**：

```
窗口高度 = 120（气泡区） + 520 × 倍率
画布高度 = 520 × 倍率
模型缩放 = 画布高度 / 模型原始高度
```

主进程 `applySize(f)`：

1. `win.setBounds(...)` 改窗口高度（**底边保持不动**，向上长）
2. `saveState({x, y, size: f})` 持久化
3. IPC `set-size` 通知渲染进程

渲染进程 `setSize(f)`：

1. `app.renderer.resize(380, 520*f)`
2. 同步 canvas / `#stage` 的 CSS 高度
3. `fitScale = null; fit()` → 重算铺满缩放
4. 气泡 `bottom` 跟着改成 `520*f - 12`
5. 命中矩形重新上报

### 踩到的坑

`index.html` 里原来写着 `#stage canvas { height: 520px !important; }`，
**`!important` 会覆盖 JS 设置的行内样式** → 画布缓冲区变成 728 但显示还按 520 挤，
于是她既没变大、脚下还多出一片空白。去掉 `!important` 后正常。

### 持久化

- **唯一真相在主进程**：`window.json` 的 `size` 字段；启动时据此决定窗口高度，并通过 `did-finish-load` 下发给渲染进程
- （早期版本渲染进程也存了 localStorage，两边会打架导致窗口与画布高度不一致，已移除）

**托盘菜单**「把她叫回任务栏（救回）」 | 点一下 |
**全局热键** `Ctrl + Alt + R` | 任何时候 |
**启动自检** `ensureOnScreen()` | 启动时若窗口与屏幕交集 < 120px → 自动救回 |
**尺寸保护** | 请求的窗口高度超过工作区时，自动把倍率压到能放下为止 |

救回动作：移到主屏工作区右下角、`showInactive()`、重新置顶、写回 `window.json`。

实测日志：

```
[rescue] test -> 1116 272
```

（`window.json` 也同步写成了 `{"x":1116,"y":272,"size":1}`）

### 仍然存在的限制

- 越出屏幕的那部分画布**点不到**（命中矩形在窗外）
- 若窗口大部分在屏幕外，虽然还在跑，但只能靠救回键找回来
- 多显示器时救回目标是**主屏**，不会回到原来那块屏

## M3.5：修复「拖动时相对鼠标越拖偏低」

**现象**：按住她拖动，她会一直相对光标向下（向后）偏，越拖越明显。

**根因：锚点取晚了**

拖拽是"锚点 + 绝对差值"：

```js
ny = anchor.by + (cursor.y - anchor.cy)
```

算式本身不累积。但锚点是在**主进程**的 `beginDrag()` 里用
`screen.getCursorScreenPoint()` 取的，而 `beginDrag` 要等
`mousedown → IPC → 主进程` 这一圈才执行。

如果按下之后**立刻就开始移动**（快速拖拽必然如此），锚点取到的是
**已经偏移过的光标位置**，于是整段拖拽都落后"按下到 beginDrag 之间"的位移。
每次拖都会发生，所以感觉像是持续偏移。

**修复（三处）**

1. **锚点用按下瞬间的坐标** —— 渲染进程把 `mousedown` 的 `screenX/screenY`
   一起通过 IPC 传给主进程，不再让主进程自己事后采样
2. **重复 mousedown 不再重置锚点**（`if (dragStart) return`）
3. **每帧检测外部干扰**：实际位置与上次请求差 >2px（尺寸变化 / 系统钳制）→ 重新锚定

另外拖拽过程中就按 `MIN_VISIBLE` 钳制到屏幕范围，撞边时把锚点挪到边界，
不再依赖系统来"帮我们夹"。

**验证**

| 测试 | 结果 |
|---|---|
单步拖动（光标 -160px） | 窗口 delta y = **-160** ✅ 完全 1:1 |
上下往返（终点回到起点） | 窗口 delta = **(0, 0)** ✅ 无累积漂移 |

## M3.6：眩晕表现（按规格表）

| 项 | 值 |
|---|---|
动作 | `TapFace[1]`（m_02 类） |
时长 | **4.57s**（`DIZZY_DUR`，与动作时长一致） |
参数 | `ParamStar` 星环 + `ParamStartRuning` 旋转 + `ParamTear` 泪 + `PARAM_CHEEK` 脸红 + `PARAM_EYE_L/R_OPEN=0` 闭眼 |
触发 | **甩飞**（拖动速度 > 1200 px/s 累计 > 300ms）／右键菜单「眩晕」／`window.__react('dizzy')` |
结束 | 最后 0.4s 整体淡出 → `resetPose()` 复位全部参数 |

实现要点：

- 眩晕期间每帧把**手臂/腿参数钉回 0**（`PIN_ARMS`），避免动作把手臂举起来
- 参数写入发生在 `motionManager.update` **之后**，所以能覆盖动作曲线
- 结束时 `resetPose()` 一并清掉星环/泪/脸红，不会残留
- 实测动作到复位间隔 4.76s ≈ 4.57 + 帧对齐

## M3.7：甩飞眩晕改为「拖动中触发 + 松手后 1 秒尾迹」

### 触发时机

| 之前 | 现在 |
|---|---|
松手时才判定 | **拖动过程中**实时判定，达标立刻开始晕 |

判定用 250ms **滑动窗口**平均速度，带滞回：

```
进入：窗口内位移 > 40px 且 平均速度 > 900 px/s
维持：平均速度 > 600 px/s
退出：< 600 px/s
```

### 持续时长

```
拖动中：主进程每 120ms 发一次 fling-hold → 眩晕截止时间 = 现在 + 1000ms
松手：再补发一次 fling-hold → 从【松手那一刻】算 1 秒
到点：0.4s 淡出 → resetPose()
```

所以 **总时长 = 拖动时长 + 1 秒（+0.4 秒淡出）**。

### 实测

```
[fling] enter avg 1077 winD 65          ← 拖动中进入
[pet] dizzy on
[main] fling ended -> dizzy tail from release   ← 松手
[pet] pose reset                         ← 54.471，松手(53.056) + 1.0s + 0.4s 淡出
```

### 表现

星环 `ParamStar` + 旋转 `ParamStartRuning` + 泪 `ParamTear` + 脸红 `PARAM_CHEEK=0.9` + 闭眼；
动作 `TapFace[1]` 只在**首次进入**时播一次（时长不够撑就一直用参数维持）；
每帧 `PIN_ARMS` 钉住手臂，避免动作把手举起来。
