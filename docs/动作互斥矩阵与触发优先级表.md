## 一、层级模型

| 层 | 语义 | 动作 | 规则 |
|---|---|---|---|
| L0 | 召唤演出 | A01 | 显示/唤出瞬间，绝对抢占，吞掉全部输入 |
| L1 | 眩晕 | A12 / A13 / A33 | PIN_ARMS 钉手臂 + 闭眼 + 脸红 + 星环 + 泪 |
| L2 | 玩家触摸 | A07~A11 | 区域命中即播，抢占 L3~L6 |
| L3 | 右键点播 | A19~A34 | 显式输入，抢占 L4~L6；序列动作可排队 |
| L4 | 剧情调度 | A35~A47 | 与待机共用 25~50s 冷却池 |
| L5 | 待机调度 | A14~A18 | 静置 15s 起算，与剧情同池互斥 |
| L6 | 常驻微动画 | A02~A06 | 每帧写参；动作期间 applyParams 直接返回 |

**同层规则**：后到者丢弃（不排队）——唯一例外是 H/B/W 三组的多段序列动作（竖起→保持→恢复 / 耷拉→恢复 / 抬起→甩动→放下），它们按深度 1 排队，否则序列语义丢失。

**跨层规则**：高层抢占低层时，低层**丢弃不复播**（除 A14/A15 待机在松手/输入结束后重新起算冷却）。

## 四、统计与结论

- 丢弃 **89** / 排队 **5** / 可叠加 **6**（共 100 对）
- **结论1**：矩阵被「丢弃」主导不是判断偷懒，而是架构决定的——`applyParams` 在动作期间直接返回 + 单 motion 通道，任意两个 playMotion 类动作天然互斥。
- **结论2**：真正的「可叠加」只存在于常驻微动画之间（A02~A06 五个通道参数不交叉），它们不是动作，是每帧程序写入。
- **结论3**：真正需要「排队」的只有 5 对，全部落在 H/B/W 的多段序列上。若把右键菜单改成「序列一次下发」，排队深度 1 就够；否则每次右键都该走丢弃。
- **结论4**：`A12` 甩飞 与 `A13` 摇晃眩晕 同帧命中会让位给 A12，因为 A12 有「松手后 1s 固定尾迹」，A13 时长随晃动浮动——先到者不定，用固定尾迹者收口。
