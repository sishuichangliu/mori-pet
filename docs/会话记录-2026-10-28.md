## 六、M3.3 大小菜单

**需求**：右键调整她的大小。

**关键**：不是简单缩放模型（会顶出画布被裁头），而是**窗口 + 画布一起长高**：

```
窗口高度 = 120（气泡区） + 520 × 倍率
画布高度 = 520 × 倍率
模型缩放 = 画布高度 / 模型原始高度
```

档位：60% / 75% / 100% / 125% / 150% / 175%。

**踩坑**

- `#stage canvas { height: 520px !important; }`：`!important` 覆盖了 JS 行内样式 →
  画布缓冲区变了但显示没变，人没变大、脚下多一块空白
- 主进程 `window.json` 与渲染进程 `localStorage` 各存一份尺寸 → 两边打架，
  窗口与画布高度错位。改为**唯一真相在主进程**，启动时主动拉取（`get-size`）

## 八、拖拽问题的长线排查（M3.5 ~ M3.8）

这是整个项目最曲折的一段，前后返工 5 次。

### 8.1 现象演进

| # | 阿源反馈 | 我当时的判断 |
|---|---|---|
1 | 拖不动到桌面边缘 | 布局问题（留白） |
2 | 移动时相对鼠标**一直向下** | 锚点取晚了 |
3 | 还有偏差 | 单位不一致 |
4 | 换成原生拖拽 | 透明窗口不支持 → 回退 |
5 | 拖动后**向下掉出桌面** | 反馈环（screenY 含窗口位置） |
6 | 现在无法拖动 | 穿透判定死锁 |

### 8.2 真凶（按发现顺序）

**① 锚点取晚（M3.5）**

```js
ny = anchor.by + (cursor.y - anchor.cy)
```

算式不累积，但锚点在主进程 `beginDrag()` 里取，要等
`mousedown → IPC → 主进程` 一圈。快速拖动时锚点已经是**偏移后**的位置。

修：渲染进程把 `mousedown` 的 `screenX/screenY` 一起传过去。

**② 坐标单位不一致（M3.6 前后）**

实测 `devicePixelRatio = 1.25`，且
`screen.getCursorScreenPoint()` 与 `win.getBounds()/setPosition()` **不在同一坐标系**
（日志中多次出现比值 0.8 = 1/1.25 / 0.995 等）。

**③ 反馈环（M3.7）—— 这一条才是“一直向下掉”的根因**

`MouseEvent.screenY = 窗口位置 + 光标在窗口内的位置`。
窗口一往下移，`screenY` 跟着变大 → 下一帧算出的位移更大 → 窗口再下移……

```
窗口下移 → screenY 变大 → 位移变大 → 窗口下移更多 → …
```

修：改用 `movementX / movementY`（鼠标硬件增量，与窗口位置无关）：

```js
win.setPosition(b.x + dx, b.y + dy)   // dx/dy 来自 movementX/Y
```

实测：12 次 `movement(30,12)` → 窗口位移 `+260,+144`（≈ 0.8×，符合 DPR），
不再有额外漂移。

**④ 穿透判定死锁（M3.8）**

```
主进程：等渲染进程说“鼠标在她身上” → 才关穿透
渲染进程：等收到 mousemove → 才能判断
窗口：穿透中 → 事件进不来
```

修：穿透判定**整体交给主进程轮询**（光标是否在窗口矩形内），
渲染进程的 `set-ignore` 降级为只记日志。

实测：

```
[ignore] receive cursor 1123 731 win 1116 272 383 640
[drag] begin window 1116 272
[main] drag stats windowDelta 96 48      ← 光标 96,60 物理 → 窗口 96,48 物理，1:1
```

### 8.3 原生拖拽为何放弃

探测结果：

```
stageRegion: "drag"   canvasRegion: "drag"   elemAt: "CANVAS"
```

样式生效，但窗口不动 —— **透明窗口（WS_EX_LAYERED）不支持
`-webkit-app-region: drag` 的系统拖拽**。方案作废，回退 JS 拖拽。

### 8.4 窗口“膨胀 / 掉出桌面”

现象：窗口从 382×640 涨到 **6756×6787**。

处理：

- 拖拽结束**只 `setPosition`，不改尺寸**
- 看门狗（800ms）：尺寸异常或位置不可达 → 自动救回
- 可抓取范围：底部至少留 160px、最多露 60px 出屏幕顶部
- 尺寸漂移自愈：偏差 >6px 就矫正

```
[watchdog] size drift {"width":384,"height":656} -> want 380 640
```

## 九、M3.6 / M3.7 眩晕与甩飞

### 规格（阿源给的）

| 项 | 值 |
|---|---|
表情 | 眩晕 |
动作 | dizzy（TapFace[1]） |
表现 | 星环 + 泪 + 脸红 + 闭眼 |
时长 | 4.57s |
触发 | 甩飞 |

### 实现

```js
ParamStar        // 星环
ParamStartRuning // 星环旋转
ParamTear        // 泪
PARAM_CHEEK      // 脸红
PARAM_EYE_*_OPEN // 闭眼
PIN_ARMS         // 每帧钉住手臂，防动作举手
```

### M3.7 改为“拖动中触发 + 松手后 1 秒”

- 判定：250ms 滑动窗口平均速度，**滞回**（进入 900 / 维持 600 px/s）
- 拖动中：每 120ms 发 `fling-hold` → 截止时间 = 现在 + 1000ms
- 松手：再补发一次 → **从松手算 1 秒**
- 到点：0.4s 淡出 → `resetPose()`

实测时间线：

```
52.655  [pet] dizzy on
53.056  [main] fling ended -> dizzy tail from release
54.471  [pet] pose reset        ← 松手 + 1.0s + 0.4s
```

> 之前不触发的原因：算的是**单帧瞬时速度**，且 `dt` 被强制最小 8ms，
> 真实事件合并后几乎到不了 1200 px/s。改为整段平均速度后正常。
